# Reproducing Every Finding in the Whitepaper

> Every numerical claim and figure in `WHITEPAPER.md` is reproducible from
> commands documented here. The instructions are organized to match the
> paper's section structure so you can verify any finding by jumping to its
> section number.

## Setup (one-time, ~3 minutes)

```bash
# Clone the repository
git clone https://github.com/nebulaidigital/whitepaper.git
cd whitepaper

# Check out the simulator branch
git checkout claude/economic-model-simulator-p2Bul

# Create a clean Python 3.11+ environment (recommended)
python -m venv .venv
source .venv/bin/activate          # Linux/Mac
# .venv\Scripts\activate            # Windows

# Install dependencies
pip install -e ".[dev]"
# Or with uv (faster): uv sync

# Verify the install: 57 tests should pass in ~15 seconds
make test
```

If `make test` does not show `57 passed`, stop and read the error.
Do not proceed to reproduce findings against a model that fails its own
test suite.

## Reproducing Section 1.1 (the empty quadrant)

The paper's Table 1.1 shows four published scenarios and one simulated
Patchwork baseline.

**The Patchwork row is reproduced by:**

```bash
make baseline
```

You should see output similar to:

```
=== STATUS QUO BASELINE — Q1 2026 trajectory continuation ===
...
US labor share:   0.589 → 0.560     (backtest 2015-2025, matches BLS)
US labor share:   0.560 → 0.510     (forward projection 2025-2036)
US top 1% wealth: 0.279 → 0.304     (matches SCF)
US top 1% wealth: 0.304 → 0.335     (forward projection)
US cumul real GDP growth: 26.0%     (matches BEA)
US cumul real GDP growth: 27.0%     (forward projection)
```

If these numbers don't match the paper, your simulator has drifted from
the documented calibration — check `src/core/simulator.py:SimulatorConfig`
for changes against the committed version on `claude/economic-model-simulator-p2Bul`.

The other three scenarios in Table 1.1 (Slow Diffusion, Goldman Base, SF
Consensus) are inputs to the comparison — they are pulled from the cited
sources directly (Acemoglu 2024 NBER WP 32487, Briggs & Kodnani 2023,
IMF SDN/2026/001). No replication code; treat as published forecasts.

## Reproducing Section 3.3 (cross-class welfare matrix)

Figure 3 plots the by-decile welfare delta matrix. Regenerate:

```bash
python -m src.analysis.chart_builders --fig 3
```

For the raw numerical matrix:

```bash
python -c "
from src.stability import CrossClassTest
from src.packages import ALL_PACKAGES
import numpy as np
np.set_printoptions(precision=2, suppress=True)

for pkg in ALL_PACKAGES:
    if pkg.code == 'A':
        continue
    result = CrossClassTest(pkg).run()
    print(f'Package {pkg.code} ({pkg.name[:30]}):')
    print(f'  Matrix (rows=deciles 1-10, cols=[US, CN]):')
    print(f'  {result.welfare_delta_matrix * 100}')
    print(f'  N positive cells: {result.n_cells_positive}/20')
    print(f'  N negative cells: {result.n_cells_negative}/20')
    print(f'  Most disadvantaged: decile {result.most_disadvantaged_cell[0]} in {result.most_disadvantaged_cell[1]} at {result.most_disadvantaged_delta * 100:+.2f}%')
    print()
"
```

To test the framework's claim about strictly-positive median-voter
sufficiency (Hypothesis 4 in PREREGISTRATION.md):

```bash
python -c "
from src.stability import CrossClassTest
from src.packages import NEBULAI_SIX, DIRECT_REDISTRIBUTION
import numpy as np

# Hypothesis 4: every decile must be strictly positive
for pkg in (NEBULAI_SIX, DIRECT_REDISTRIBUTION):
    m = CrossClassTest(pkg).run().welfare_delta_matrix
    strictly_positive = np.all(m > 0)
    non_negative = np.all(m >= -1e-9)
    print(f'{pkg.code}: strictly positive = {strictly_positive}, non-negative = {non_negative}')
"
```

If `Package B: strictly positive = False, non-negative = True`, the
paper's Section 3.3 finding is replicated.

## Reproducing Part VI (limitations stress tests)

The four stress tests are in `src/stability/`. Run all of them across
the major packages:

```bash
python -c "
from src.stability import DefectionTest, CoalitionTest, TimeConsistencyTest, CrossClassTest
from src.packages import NEBULAI_SIX, CERN_AI, GAME_THEORETIC, DIRECT_REDISTRIBUTION

for pkg in (NEBULAI_SIX, CERN_AI, GAME_THEORETIC, DIRECT_REDISTRIBUTION):
    print(f'=== {pkg.code}: {pkg.name} ===')

    df = DefectionTest(pkg)
    df_results = df.run()
    df_summary = df.summary(df_results)
    print(f'  Defection: {df_summary[\"n_defections_tested\"]} tested, {df_summary[\"n_fragile\"]} fragile')

    cl = CoalitionTest(pkg).run(n_steps=8)
    print(f'  Coalition breakeven: {cl.breakeven_threshold:.2f} (spec: {cl.package_threshold_specified:.2f}, consistent: {cl.threshold_consistency})')

    tc = TimeConsistencyTest(pkg, n_draws=50).run()
    print(f'  Time-consistency loss from political risk: {tc.welfare_loss_from_political_risk:.2f}')
    print(f'  Most vulnerable lever: {tc.most_vulnerable_lever}')

    cc = CrossClassTest(pkg).run()
    print(f'  Cross-class: {cc.n_cells_positive}/20 cells positive, fails H4 (strict): {cc.n_cells_negative > 0 or cc.most_disadvantaged_delta <= 0}')
    print()
"
```

## Customizing the experiments

### Change a baseline calibration parameter

Edit `src/core/simulator.py:SimulatorConfig`. For example, to test a
higher AI productivity growth scenario:

```bash
python -c "
from src.core import BilateralSimulator, SimulatorConfig
sim = BilateralSimulator(config=SimulatorConfig(ai_productivity_growth=0.045))
df = sim.run().to_dataframe()
print(df.loc[2036, ['us_real_gdp', 'us_top_1pct', 'us_labor_share']])
"
```

### Change a Pillar effect size

Edit the relevant lever's `parameter_changes` dict in
`src/packages/nebulai_six.py`. For example, to test a stronger Pillar 1:

```python
PILLAR_1_SOVEREIGN_EQUITY = PolicyLever(
    ...
    parameter_changes={
        "sovereign_acquisition_fraction": 0.20,   # changed from 0.10
        "cost_of_equity_premium": 0.010,           # accordingly
        "dividend_rate": 0.04,
    },
    ...
)
```

Then re-run `make packages` to see the comparative effect.

### Add a new policy package

Copy `src/packages/direct_redistribution.py` to
`src/packages/your_package.py`, modify the levers, then register in
`src/packages/registry.py`:

```python
ALL_PACKAGES = (
    STATUS_QUO,
    NEBULAI_SIX,
    CERN_AI,
    COMPUTE_CENTRIC,
    DIRECT_REDISTRIBUTION,
    BUILD_DIFFERENT,
    GAME_THEORETIC,
    YOUR_PACKAGE,    # add this
)
```

Then `make packages` and `make rdm` will automatically include the new
package in comparisons.

### Add a new RDM uncertainty dimension

Edit `src/analysis/rdm.py:UNCERTAINTY_RANGES`:

```python
UNCERTAINTY_RANGES = {
    ...existing...
    "your_new_parameter": (lower, upper),
}
```

Then add the same parameter to `make_simulator_function` so it gets
passed through to the simulator. The LHS sampler picks it up
automatically.

## What to do if you disagree with a finding

The methodology is designed to make disagreements parameterizable:

1. **Identify which lever or parameter you disagree with.**
2. **Edit its value in the appropriate `src/packages/*.py` file.**
3. **Re-run `make packages` and `make rdm`** to see how the comparative
   result changes.
4. **Document your reasoning** in a comment on the parameter change.

The framework is designed to integrate disagreement into the analysis
rather than to settle disagreement by authority.

## What to do if the simulation behaves unexpectedly

1. Confirm `make test` passes (57/57).
2. Confirm `git log --oneline` shows the expected commits on the
   `claude/economic-model-simulator-p2Bul` branch.
3. Check `BASELINE_2026.md` matches the trajectory you expected.
4. Inspect the simulator's audit trail:

```bash
python -c "
from src.core import BilateralSimulator
from src.packages import NEBULAI_SIX
sim = BilateralSimulator()
result = sim.run(package=NEBULAI_SIX, coalition_share=0.7, cn_cooperation=0.5)
for entry in result.audit_trail:
    print(entry)
"
```

Audit-trail entries are `(lever_name, parameter, operation, value)`
tuples documenting exactly which lever modified which simulator
parameter.

5. If you find a genuine inconsistency between paper claim and simulator
output, the paper claim is wrong — please open an issue on the companion
repository.
